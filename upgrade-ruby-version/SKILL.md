# Upgrade Ruby Version

Upgrade the runtime consistently, refresh only Ruby lock metadata, then run every verification surface already provided by the repository.

## Inspect

- Read repository instructions and determine the requested target version. Ask only when no target version is given.
- Preserve unrelated staged and unstaged changes.
- Inspect `Gemfile`, `.ruby-version`, `mise.toml` when present, `.gitlab-ci.yml` and included local CI files.
- Discover the repository's test, lint, security, build, Zeitwerk, and aggregate local-CI commands before editing.

## Update

Apply the exact target version consistently:

- Update the `ruby` declaration in `Gemfile`.
- Update every Ruby image version in `.gitlab-ci.yml` that executes project jobs. Preserve registry names, image variants, variables, and quoting style.
- Update the Ruby tool entry in `mise.toml` only when the file exists.
- Update `.ruby-version`.

Do not update unrelated dependencies or runtime images.

Activate the target Ruby. When the repository uses mise, run `mise install` if required and verify with `mise exec -- ruby -v`. Then run:

```sh
bundle update --ruby
```

Confirm `Gemfile.lock` changed only as expected and its `RUBY VERSION` matches the target interpreter and patchlevel format generated by Bundler.

## Verify

Run the repository's complete local CI command when available, such as `bin/ci`. Read it first, then run any relevant checks it does not cover. Use repository wrappers in preference to invented commands.

Run applicable checks, including:

- dependency installation/check;
- Rails Zeitwerk check;
- full RSpec or other complete test suite;
- Bundler Audit with an updated advisory database when configured;
- RuboCop, Brakeman, type checks, gem build, or other repository-provided gates;
- application boot or built-gem load smoke;
- `git diff --check`.

Do not skip or weaken a failing check. Diagnose failures caused by the new Ruby version; report pre-existing or environmental failures separately with exact commands and output summaries.

## Finish

- Review the complete diff and confirm all Ruby version sources agree.
- Report changed files, old and new versions, checks with pass/fail status, and remaining blockers.
- Do not commit, tag, push, publish, or deploy unless explicitly requested.
